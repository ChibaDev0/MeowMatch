## 2. P5-02 / RES-01 — คำตัดสินที่ต้องขอ

ทุกแถวด้านล่างเป็น **OPEN** ข้อเสนอเป็นคำถามเพื่อขอการตัดสิน ไม่ใช่นโยบายที่ได้รับอนุมัติแล้ว ผู้ทบทวนควรเป็นสัตวแพทย์ที่มีความเชี่ยวชาญด้านสุขภาพ/การสืบพันธุ์และสวัสดิภาพของแมว ร่วมกับผู้เชี่ยวชาญพันธุศาสตร์เมื่อเกี่ยวกับ variants

| ID | คำตัดสินที่ต้องบันทึก | หลักฐาน/ข้อมูลที่ต้องให้ | เกณฑ์นำไปตรวจซอฟต์แวร์ |
|---|---|---|---|
| EX-W01 | เมื่อพบ welfare finding ระดับคู่ ให้ pair ระงับทุก trait หรือแสดงบาง trait เพื่อการศึกษาได้? target ต้องตัดทั้งคู่เสมอหรือไม่? | ตารางผลที่อนุญาตของแต่ละโหมด เหตุผลทางวิชาชีพ และข้อความผู้ใช้ที่รับรอง | ใช้คู่เดียวกันผ่านสองโหมด รวมการขอ coat_type อย่างเดียว; ไม่มีทางเลี่ยงข้อห้ามด้วยการไม่เลือก ear_type |

## 3. P5-03 — ชุดกฎที่เปิดได้จริง

ให้พิจารณาทีละ ruleset/variant และทีละขอบเขตข้อมูล ห้ามอนุมัติทั้งหมวดเพียงเพราะหนึ่งตัวอย่างคำนวณถูก

| ขอบเขต | สถานะจากโค้ด | คำตัดสินที่ต้องขอ |
|---|---|---|
| coat_type: short/long | demo เท่านั้น | EX-G01: variants และชุดผลตรวจใดรองรับได้จริง; ยอมให้ phenotype-only ระบุ genotype ได้ในเงื่อนไขใดหรือไม่ |
| hairless | ไม่มี outcome ในกฎขนสาธิต | EX-G02: คง unsupported จนมี ruleset แยกที่มีหลักฐาน ห้ามแทนด้วยโอกาส 0 |
| coat_color / coat_pattern / eye_color / ear_type | ไม่มี ruleset ใน registry ที่ตรวจ | EX-G03: traits ใดอยู่ใน release; ที่เหลือประกาศ unsupported พร้อมเหตุผล |
| หลาย trait พร้อมกัน | มี guard ปิด joint ที่ไม่มีโมเดล | EX-G04: ยังไม่เปิดจนมีโมเดล dependency/phase/linkage/interaction ที่เหมาะกับขอบเขตและ fixtures; ห้ามคูณ marginal ตามความสะดวก |
| Bayesian prior / หลายรุ่น | ไม่เป็นเงื่อนไขเปิด single-locus demo | EX-G05: หากไม่มีข้อมูลรับรองให้ปิดโหมด ไม่ตั้ง prior เท่ากันเอง และไม่ขยาย scope อัตโนมัติ |

### แฟ้มหลักฐานบังคับต่อ ruleset

1. **ตัวตนและขอบเขต:** rule ID, version, artifact digest, trait/outcome codes, gene/locus/variant identifiers และ reference convention ที่ใช้, assay/lab panel ที่ครอบคลุม, ประชากร/สายพันธุ์ที่ผลนำไปใช้ได้ และรายการที่ไม่รองรับ
2. **สมมติฐาน:** inheritance model, genotype→outcome mapping, penetrance/expressivity ตามขอบเขตที่อ้าง, variant interaction/phase หากเกี่ยวข้อง, วิธีใช้ phenotype-only, ข้อจำกัดการตรวจและการตีความผลลบ แยก “ไม่พบ variant ที่ตรวจ” จาก “ไม่มี variant ที่เกี่ยวข้องทั้งหมด”
3. **หลักฐานอ้างอิง:** ชื่อเอกสาร ผู้แต่ง/หน่วยงาน DOI หรือ URL รุ่นเอกสาร/วันที่เผยแพร่ วันที่เข้าถึง หน้า/ตาราง/ข้อความที่รองรับกฎ พร้อมเหตุผลเชื่อมหลักฐานกับ mapping แต่ละข้อ; ระบุช่องว่างและหลักฐานที่ขัดแย้ง
4. **ผู้ทบทวน:** ชื่อจริง บทบาท/คุณสมบัติและขอบเขตความเชี่ยวชาญ ผู้ตรวจทางพันธุศาสตร์และ welfare ตามส่วนที่รับผิดชอบ วันที่ตัดสิน เขตเวลา รุ่นที่ลงนาม เงื่อนไขและเหตุผล ห้ามกรอกชื่อ/วันที่อนุมัติแทนผู้เชี่ยวชาญ
5. **Fixtures อิสระ:** inputs, expected genotype/outcome probabilities หรือ expected status, วิธีคำนวณ/แหล่งเฉลย, ผู้จัดทำ/ผู้ตรวจ และ hash ของชุดข้อมูล เฉลยต้องไม่สร้างจาก production function ที่กำลังตรวจเอง
6. **อายุการรับรอง:** review trigger เมื่อหลักฐาน/assay/model เปลี่ยน ผู้รับผิดชอบการเพิกถอน และวิธีหยุดใช้เวอร์ชันที่มีปัญหา การแก้ substantive rule ต้องได้รับ review ใหม่ ไม่แก้ artifact เดิมแล้วคง version เดิม

### ชุด fixtures ขั้นต่ำที่ต้องให้ผู้เชี่ยวชาญตรวจเฉลย

- คู่ genotype ที่อยู่ในขอบเขตครบทุกกลุ่ม รวม carriers และผลที่เป็นศูนย์จริง
- Allele/variant ที่ไม่อยู่ในโมเดล, phenotype ไม่ทราบ/กำกวม, หลักฐานขัดกัน, ข้อมูลไม่ครบ และผลตรวจคุณภาพไม่ผ่าน
- Scenario set ที่ไม่มี prior: expected min/max จากทุกกรณีที่ครอบคลุม ไม่เฉลี่ยเป็น point estimate
- Variant combinations และ phase ที่โมเดลอ้างว่ารองรับ; ที่ยังไม่รองรับต้องคืนสถานะตามสัญญา
- Welfare gates ทั้งที่ตั้งเป้าลักษณะต้องห้ามและเป้าหมายอื่น; hard block ไม่ถูกคะแนน override
- สลับลำดับพ่อแม่/alleles แล้วผลเหมือนกันเฉพาะกรณีที่โมเดลระบุ symmetry; ไม่บังคับ symmetry กับโมเดลที่มีเงื่อนไขเพศต่างกัน
- ถ้ามีคำตอบจำนวนลูก: แยกกรณีทราบ genotype จาก shared-parent uncertainty; สูตรอิสระใช้ได้เฉพาะสมมติฐานที่รองรับ

ผ่าน fixtures คณิตศาสตร์อย่างเดียวไม่เพียงพอสำหรับเปลี่ยน verified=true

## 4. Workflow รับรอง DNA และ consent ที่ต้องตกลง

ข้อเสนอต่อไปนี้เป็น workflow สำหรับรับ review ยังไม่ใช่สถานะระบบที่ implement แล้ว และไม่แทนคำตัดสินด้านสิทธิ์/นโยบายข้อมูลโดยเจ้าของผลิตภัณฑ์

| ขั้น | ผู้รับผิดชอบ/คำตัดสิน | หลักฐานและข้อกำหนดตรวจรับ |
|---|---|---|
| 1. รับเอกสาร | เจ้าของข้อมูล + ทีมผลิตภัณฑ์กำหนดสิทธิ์อัปโหลด/ใช้ | ผูก cat ID, sample identity, lab/report ID, วันที่เก็บ/ตรวจ, panel version; เอกสาร private; กดใจ/เผยแพร่ listing ไม่เท่ากับอนุญาตใช้ DNA |
| 2. ตรวจความยินยอม | เจ้าของข้อมูล/ผู้มีอำนาจ + ผู้รับผิดชอบนโยบายข้อมูล | ระบุผู้ให้สิทธิ์ วัตถุประสงค์ pair/target/history/replay การแบ่งปัน ระยะใช้งาน policy version และเวลา; แยกจากการรับรองความถูกต้องทางวิทยาศาสตร์ |
| 3. ตรวจหลักฐาน | ผู้ตรวจ DNA ที่ได้รับมอบหมาย | ตรวจตัวตนตัวอย่าง ความครบ/คุณภาพ panel coverage และความขัดแย้ง; กำหนด accepted/rejected/needs-review พร้อมเหตุผล ห้าม client กำหนด accepted เอง |
| 4. แปลงข้อมูล | ผู้เชี่ยวชาญกำหนด mapping; server ดำเนินการ | ใช้ allele/variant nomenclature และ ruleset version ที่อนุมัติ; missing/no-call ไม่กลายเป็น normal allele; เก็บผู้ตรวจและ mapping version |
| 5. อนุญาตใช้ | Server ตรวจสถานะและสิทธิ์ปัจจุบันทุกครั้ง | หลักฐานต้อง accepted, consent ใช้ได้, rule approved และอยู่ใน scope; verification ของรายงานกับ approval ของ rule เป็นคนละสถานะ |
| 6. แก้ไข/ถอน | เจ้าของข้อมูลและผู้รับผิดชอบนโยบาย; ผู้เชี่ยวชาญเมื่อเพิกถอนหลักฐาน | กำหนดการ invalidate/redact/cache/replay ของผลเดิมและเส้นทางแจ้งผู้เกี่ยวข้อง; ห้ามผลเก่าถูกใช้ต่อโดยข้ามการถอนสิทธิ์ |

รายละเอียด retention/redaction และกลไก DB ต้องส่งต่อทีม P5-04/P5-05 ออกแบบและทดสอบจริง เอกสารนี้ไม่เลือกคำตอบแทนผู้มีอำนาจและไม่อ้างว่าปฏิบัติตามกฎหมายแล้ว

## 6. เกณฑ์ปิดงานและสิ่งที่ทีมทำต่อได้

**ทีมซอฟต์แวร์ทำได้ก่อนคำอนุมัติ:** เตรียม schema ของ decision records, fixture harness, provenance, UI states และ tests ของสถานะ pending/unsupported/revoked โดยคง demo gate ไม่ใช้สมมติฐานใหม่เป็นกฎจริง

**P5-02 ปิดได้เมื่อ:** EX-W01–07 มีคำตัดสินในขอบเขต release; pair/target ใช้นโยบายเวอร์ชันเดียวกัน; expected behavior/ข้อความ UI ผ่านผู้ทบทวน และมีการทดสอบ implementation เทียบ decision table

**P5-03 ปิดได้เมื่อ:** แต่ละ trait ที่ประกาศเปิดมีแฟ้มหลักฐานครบและ approved record ผูกกับ artifact/fixtures; DNA workflow ผ่านการรับรองและทดสอบเท่าที่ release ใช้; traits ที่เหลือปิดอย่างชัดเจน การอนุมัติให้คง demo เป็นการจำกัด release ไม่ใช่การรับรองผลจริง

**ลำดับส่งขอ review:** ตกลง trait/release scope → ตัดสิน welfare/unknown-sex policy → ตรวจแฟ้มกฎและเฉลย → ตกลง DNA evidence/consent workflow → ลงนาม record → ทีม implement และทดสอบ → จึงพิจารณาเปิด rule ที่รับรองแล้ว

ยังต้องตรวจ P5-05 บน DB จริง, P5-07 ด้วย benchmark และ P5-08 ผ่าน app/E2E แยกต่างหาก P5-04 อยู่ระหว่างดำเนินการโดยแชทหลัก ไม่มีรายการเหล่านี้ผ่านหรือปิดด้วยเอกสารฉบับนี้
