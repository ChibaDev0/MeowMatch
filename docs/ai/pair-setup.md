# หน้าผสมพันธุ์: ข้อมูลสองตัว → ลักษณะลูก

อัปเดต 2026-10-13

## ใช้งาน

1. ไปแมวของฉัน → แก้ไขแมว → เติมสีขนและลวดลายขนที่ทราบ แล้วบันทึก
2. หน้าผสมพันธุ์ เลือกสองตัวแล้วกดวิเคราะห์ลูกแมว
3. ผลแสดงข้อมูลทั้งคู่และห้าหมวดของลูก พร้อมเงื่อนไขและแหล่งผลรายหมวด

คีย์ใช้ `GEMINI_API_KEY` ฝั่งเซิร์ฟเวอร์เดิม ตั้งโมเดลแยกด้วย:

```dotenv
GEMINI_PAIR_MODEL="gemini-3.1-flash-lite"
```

หากไม่ตั้ง ใช้ `GEMINI_MODEL` แล้วจึงค่าเริ่มต้น `gemini-3.8-flash`
ตอนทดสอบ 3.8/3.5 ตอบช้าหรือ HTTP 503 ส่วน 2.5 ตอบ 404 แม้ปรากฏใน Models API
จึงตั้งโมเดลเฉพาะหน้าคู่แมวเป็น 3.1 Flash Lite หลังยืนยัน generateContent จริง ไม่เปลี่ยนโมเดลหน้าเป้าหมาย

ส่งเฉพาะเพศ พันธุ์ และรูปลักษณ์ทั้งคู่ ไม่ส่งชื่อ รหัสแมว รูป หรือข้อมูลเจ้าของ
อ่านคำสั่งจริงจาก `docs/ai/pair-appearance.md` และรวมใน Next output tracing
จำกัดคำตอบ 4096 tokens, เวลา 45 วินาที, ไม่มี retry อัตโนมัติ
ตัวจำกัดเฉพาะหน้าคู่อยู่ใน process: 20 คำขอ/นาที พร้อมกัน 2 คำขอ ไม่ใช่ distributed/per-user quota
เมื่อ API ใช้ไม่ได้ แสดงข้อมูลพ่อแม่และกฎพื้นฐาน; หมวดที่พึ่ง AI แจ้งว่ายังประเมินไม่ได้

## กฎและข้อจำกัด

- ความยาวขนใช้ scenarioBounds กับกฎสาธิตเดิม เช่น ขนสั้น × ขนยาว: ขนสั้น 50–100%, ขนยาว 0–50% ภายใต้สมมติฐาน ไม่ใช่ค่าที่วัดจริง
- กฎกลุ่มสีส้มรองรับเฉพาะสีดำ/ส้ม/แดงที่ระบุชัด ทราบเพศผู้และเมีย ไม่ใช้กับสีขาว สีผสม หรือข้อมูลสีพื้นที่ขัดกับลายสามสี/กระดองเต่า
- ไม่อนุมาน dilution, white spotting หรือโอกาสรวมหลายลักษณะ ตัวเลขไม่มีในผลสี
- แม่ดำ × พ่อส้ม แสดงกลุ่มสีดำสำหรับลูกผู้และกลุ่มกระดองเต่าสำหรับลูกเมียตามแบบจำลอง สีสามสีต้องมีแต้มขาวร่วมด้วย
- กฎหูอธิบายความเป็นไปได้โดยไม่อ้างเปอร์เซ็นต์หรือรับรองสุขภาพ ไม่มีข้อความเตือนซ้ำทุกการ์ด
- สี/ลายอื่นและสีตายังเป็นคำอธิบาย AI แบบมีเงื่อนไข อาจผิดพลาดได้ แม้ผ่าน schema

แหล่งข้อมูลหลักที่ใช้จำกัดกฎ:
- [Molecular and genetic characterization of sex-linked orange coat color](https://pmc.ncbi.nlm.nih.gov/articles/PMC12187551/)
- [UC Davis: Scottish Fold](https://vgl.ucdavis.edu/test/scottish-fold)
- [UC Davis: Long Hair](https://vgl.ucdavis.edu/test/long-hair-cat)

## ฐานข้อมูลและการตรวจสอบ

Migration `20261013075625_cat_coat_appearance.sql` เพิ่ม `cats.coat_color` และ `cats.coat_pattern`
เป็น text nullable จำกัด 80 ตัวอักษร Applied และตรวจอ่านเขียนจริงใน MeowMatch แล้ว
คง RLS/ownership เดิม ไม่ backfill สีจากรูปหรือชื่อพันธุ์ ฟอร์มเก่าที่ไม่ส่งสองช่องนี้ไม่ล้างค่าที่มีอยู่

ผลตรวจรอบสุดท้าย:
- Unit/integration ที่เกี่ยวข้อง 89 ข้อผ่าน ครอบคลุมสิทธิ์ข้อมูล เปลี่ยนคู่ระหว่างรอ ข้อมูลขาด กฎสีตามเพศ fallback และการบันทึกสี
- Browser E2E ใช้ Supabase และ Gemini จริง: สร้างบัญชีเฉพาะรอบนี้ → บันทึกแมวผ่านสิทธิ์สมาชิก → ล็อกอิน → เปิดแก้ไขและบันทึกสี/ลาย → เลือกสองตัว → แสดงผลจาก Gemini พร้อมกลุ่มสีตามเพศ ผ่าน
- ตรวจ desktop และ mobile 390px ไม่มี horizontal overflow; ตรวจภาพหน้าจอจริงแล้ว
- ลบบัญชีทดสอบหลังรัน และข้อมูลแมวที่ผูกกับบัญชีถูกลบตาม cascade
- TypeScript, ESLint และ production build ผ่าน

คำสั่งทดสอบซ้ำ (สองคำสั่งนี้เรียกบริการจริงและใช้โควตา):

```text
npm run test:gemini:live -- tests/live-gemini/pair.test.ts
npm run test:pair:e2e
```
